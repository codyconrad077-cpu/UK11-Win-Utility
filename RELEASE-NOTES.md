# 0.3 preview — Apex Tweaks

Rebranded to **Apex Tweaks**, with **made by riley**, charcoal panels and blue accents inspired by the supplied layout. General and Advanced use simple name/toggle rows, with section Apply all and global General/Advanced Revert all. The dashboard adds actual GPU usage and compatible CPU/GPU temperatures with a selector and history; unsupported readings remain unavailable.

Nine pages cover Home, System Restore, Drivers, General, Debloating, Networking, Advanced, Services and BIOS/SCEWIN. Implemented Windows workflows include restore-point creation/listing, reviewed optional Appx removal, IPv4 DNS setup/recovery, optional service changes, supported Store access policy, Windows Update GPU driver scanning/installation, third-party driver export and a fixed winget runtime set. Administrator operations use Windows UAC; installation terms are presented before approval. DDU is guided/manual. Firmware information/export is read-only.

General retains 45 distinct existing current-user preferences. Advanced selects up to 120 AC/DC endpoints from 60 power parameters and obtains targets from Windows' High Performance default APIs. It never invents missing settings or unsupported values. Availability varies; higher heat/power use and battery drain are possible. Neither endpoint counts nor API verification prove performance gains.

Legacy `%LOCALAPPDATA%\UK11Ultimate` originals remain usable across the rebrand. Per-operation JSON results and originals support visible failure/recovery. App inventory backups cannot guarantee reinstall after package files are removed. Driver archives cannot guarantee recovery from every installation failure. Service, app, DNS and driver operations are separate from the General/Advanced revert button.

Validation distinguishes portable engine fault injection, temporary registry writes, inactive duplicate-plan writes, PowerShell parsing/rejection/read-only execution, and rendered WPF navigation. Physical sensor support, actual desktop preference effects, app/service/DNS mutations and installations still need disposable Windows-client/hardware acceptance. This remains an unsigned preview, without benchmark-backed performance claims.
