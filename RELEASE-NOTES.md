# 0.2 preview — control centre redesign

The interface has been replaced with a custom WPF shell, consistent spacing/type/colour tokens, vector branding, a restrained blue palette, readable cards, real CPU/memory history, hardware identity, and an actionable catalogue workspace. The catalogue supports search, categories, state filters, favourites, selection, a persistent detail inspector and clear current/target values. Recovery has per-setting and full-restore previews plus transaction history. All visible navigation and action controls have implemented handlers.

The fixed catalogue contains **45 distinct current-user preferences**, compared with three previously. They cover Explorer, taskbar, appearance, capture, suggestions and privacy. They are not 45 measured gaming optimisations. Unknown/missing/non-DWORD values and incompatible Windows builds remain unavailable. Several preferences use legacy Windows registry contracts and may be ignored by newer builds or policy; stored-value tests do not prove their UI effect.

The new power catalogue queries Microsoft PowrProf APIs for actual subgroups, settings, descriptions, available option values and numeric bounds. Every setting exposes independently stored plugged-in and battery targets. Counts are hardware/OS dependent; these are not padded copies or 300 proven FPS optimisations. DC values can be stored on desktops without affecting a system that has no battery. Advanced controls can change sleep, battery lifetime and thermals: individual review is required. There is no automatic "maximum performance" preset or bulk power write. Unsupported/read-only targets remain visibly read-only.

Power backups capture the exact scheme GUID, subgroup, setting and AC/DC side. Descriptors for unresolved originals survive rescanning and active-plan changes. The adapter does not deliberately activate an inactive captured scheme; it reapplies only a plan observed to be active. Windows does not offer a cross-process transaction for plan switching, so external power utilities can still race with changes. Backups and the saved power catalogue must be kept together.

Preference batches preflight all targets, compare against the confirmed preview, verify every write and roll back attempted changes in reverse order when an operation fails. Failed or conflicting rollback is explicitly reported with originals retained. Full restore preserves external third values and reports each failure rather than overwriting it.

Testing distinguishes portable engine behavior, isolated native registry writes, inactive-plan power writes, WPF interaction/rendering and actual user-visible effects. The Windows UI smoke run uses a temporary data folder, never invokes mutation controls, and produces actual rendered dashboard/catalogue images. It tests search, filtering, favourites persistence and recovery navigation. It is not a human DPI/accessibility review or gaming benchmark.
