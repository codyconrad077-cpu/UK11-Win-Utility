# Windows acceptance — Apex 0.3

CI validates adapters and non-destructive workflows, not every real mutation or its user-visible effect. Before a production release, use disposable Windows 10/11 x64 clients and representative physical hardware.

1. Run `./scripts/build.ps1 -Publish`. Inspect the current native/UI JSON reports and screenshots. Keep parsed, read-only, write/restore, unavailable and unrun checks distinct.
2. Copy only Apex.Tweaks.exe to a clean client without .NET. Check standard-user launch, denied/cancelled UAC, a second instance, deferred closing during operations, and upgrade recovery from the retained UK11 data folder.
3. Compare CPU/GPU/RAM and sensor temperatures against trusted hardware tools. Missing sensors must remain unavailable; test integrated/discrete/multi-GPU systems and privilege differences. Do not disable Windows protections to obtain readings.
4. Review all nine pages at 100/150/200% DPI, minimum size and maximized. Verify keyboard focus, switches, accessible names, screen readers, readable contrast, search and chart tabs.
5. For all 45 preferences, test supported/present, absent, wrong-type and policy-overridden values. Check the actual desktop effect after any required sign-out. Verify precise originals, stale preview rejection, interrupted writes, failed batch recovery and external conflicts. A registry write alone does not establish the intended Windows UI effect.
6. For Advanced, compare target identities/defaults with Windows APIs and options/ranges. Test AC/DC independently, active/inactive plans, reboots, previous-plan originals, battery behavior and thermals. Review settings before bulk application; no universal performance benefit is established.
7. Test restore-point creation with protection enabled/disabled, frequency limits and insufficient space; creation must verify a new sequence number. Windows recovery must remain an explicit separate action.
8. Test debloat preview/cancel, the optional allowlist, protected packages, changed inventories, per-package failures, current-user scope and retained-files reinstall. Removed files may require Store/publisher reinstall. Desktop applications use Windows Installed Apps.
9. Test DNS on DHCP/static adapters, adapter disappearance, admin denial, resolution failure/verified rollback, external changes and exact original DNS mode. ICMP blocking must not be reported as proof of internet failure or gaming packet loss.
10. Test optional services originally running/stopped, automatic/manual/delayed start, running dependents, interrupted operations, restore failures and external startup-mode changes. Verify Store policy only on supported Enterprise/Education; other editions stay unavailable. Do not disable critical updating/security/driver services.
11. Test driver scans with no updates, matching/nonmatching vendors and changed update lists. Review EULAs, export drivers, verify downloads and inspect per-update result/reboot requirements. Test failed export/install, unavailable System Restore and Device Manager/recovery. Test winget absence, exact package IDs, license preview, hash/signature failures, existing packages and per-package install failures. No automatic reboot or hash bypass.
12. Confirm DDU guide links and BIOS information/export/OEM links work. No generic DDU control or SCEWIN write is implied. OEM-specific firmware automation needs validated mappings and a recovery procedure before any implementation.
13. Record repeatable before/after workload, temperature, power and battery measurements before advertising performance improvements. No “300 premium proven tweaks” claim follows from these checks.
